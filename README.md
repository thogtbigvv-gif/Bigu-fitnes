# Bigu Fitness — Дасгалын тэмдэглэл

Өдөр тутмын дасгалын төлөвлөгөөг харуулж, дасгал бүрийг гүйцэтгэх тутам todo list
шиг тэмдэглэдэг **утсанд зориулсан** вэб апп.

Гурван зарчим дээр зогсоно:

- **Build алга.** Framework, npm, bundler байхгүй — зөвхөн HTML + CSS + ES modules.
- **Гадаад холбоос алга.** CDN, library, гадны font байхгүй. Бүх зүйл repo дотроо.
- **Backend алга.** Бүх өгөгдөл хөтчийн `localStorage` дээр, тухайн төхөөрөмж дээрээ.

## Дэлгэцүүд

| Таб | Юу харуулах |
| --- | --- |
| **Өнөөдөр** | Огноо, өдрийн нэр, гүйцэтгэлийн progress, дасгалын жагсаалт. Дасгал дээр дархад сет тус бүрийг тусад нь тэмдэглэнэ. Бүгд дуусахад "дууслаа" төлөв гарна. Амралтын өдөр бол сарны тэмдэгтэй тусдаа карт. |
| **Долоо хоног** | Даваа–Ням 7 өдрийн товч тойм, аль өдөр биелсэн эсэх, долоо хоногийн сетийн хэмжүүр. |
| **Түүх** | Одоогийн цуваа, гүйцэтгэлийн хувь, дөрвөн төлөвийн тоо, доор нь **30 хоногийн чеклист** (хуанлийн тор). Мөр мөрөөр нь харах бол "Дэлгэрэнгүй". |

### Аль ч өдрийг нээж тэмдэглэнэ

**Долоо хоног** эсвэл **Түүх** дээрх аль ч мөрийг дархад тэр өдрийн дэлгэц нээгдэнэ.
Өнгөрсөн өдөр бол **тэмдэглэгээг нь нөхөж болно** — заалнаас гараад тэмдэглэхээ
мартвал тэр өдөр үүрд хоосон үлдэхээ больсон. Дээд талд гарч ирэх зурвасаар
өдрөөс өдөр рүү алхаж, "Өнөөдөр рүү буцах" товчоор эргэж ирнэ.

Ирээдүйн өдрийг **харж болно, тэмдэглэж болохгүй** — төлөвлөгөөгөө урьдчилж
үзэхэд л зориулагдсан. Гэхдээ **зөөж болно**: маргааш ажлаас ядрах нь тодорхой
бол маргаашийн бэлтгэлээ өнөөдөр эсвэл амралтын өдөр рүүгээ шилжүүлнэ
([Өдөр солих](#өдөр-солих)).

### Чеклист

Түүхийн гол хэсэг нь **хуанлийн тор**: 30 хоног 7 баганад (Даваа–Ням) орж, нэг
дэлгэцэнд багтана. Урьд нь энд 30 ширхэг бүтэн мөр байсан — гүйлгэж байж уншина,
"энэ сард би хэр тогтвортой байв?" гэсэн ганц асуултад хариулдаггүй байв.

| Нүд | Юу гэсэн үг |
| --- | --- |
| Цагаанаар дүүрсэн + чек | Биелсэн |
| Ёроолоос нь хэсэгчлэн дүүрсэн | Дутуу — дүүргэлт нь хэдэн хувийг хийснийг заана |
| Хоосон нүд | Хийгээгүй |
| Зөвхөн бүдэг тоо, зааггүй | Амралт |
| Акцент хүрээтэй | Өнөөдөр |

Нүд бүр дарагдана — тэр өдрийн дэлгэц нээгдэж, нөхөж тэмдэглэх боломжтой
(жагсаалтын мөртэй яг ижил үйлдэл).

Мөр мөрөөр нь (гарчиг, хэдэн дасгал, төлөв) харах хэрэгтэй бол доорх
**"Дэлгэрэнгүй"** задарна. Анхнаасаа хаалттай, таб солиход дахин хаагдана.

### Амралтын тоолуур

Сет тэмдэглэх бүрд тухайн дасгалын `rest` секунд ажиллаж эхэлнэ. Нэг л удаад нэг
тоолуур ажиллана.

- Сетээ буцааж тайлбал тоолуур зогсоно.
- Дасгалын **сүүлчийн** сет тэмдэглэгдэхэд тоолуур гарахгүй — амрах шаардлагагүй.
- Дуусахад "Бэлэн" болж, богино чичиргээ өгнө (дэмждэг төхөөрөмж дээр). Дуу гарахгүй.
- Тоолуур зөвхөн **өнөөдөр** ажиллана. Өнгөрсөн өдөр нөхөж тэмдэглэхэд утгагүй.
- Апп-ыг далд болгоод буцаж ирэхэд үлдсэн хугацаа зөв байна — тоо нь үргэлж
  дуусах агшнаас тооцогддог, өнгөрсөн секундүүдийг тоолдоггүй.
- **Хуудас дахин ачаалагдсан ч амралт үргэлжилнэ.** Заал дээр утас түгжигдээд
  таб сэргээгдэхэд 2 минутын амралт тэглэгдэхгүй (`sessionStorage`, `gym:timer`).
  Хөтөлбөр солигдож тухайн дасгал алга болсон бол сэргээхгүй.

### Бусад зан төлөв

- **Шөнө дунд.** Апп нээлттэй хэвээр өдөр солигдоход "өнөөдөр" аяндаа шинэ өдөр
  рүү шилжинэ (шөнө дунд яг тэр агшинд, мөн апп руу буцаж ирэх бүрд шалгагдана).
- **Хоёр таб.** Ижил аппыг хоёр табд нээвэл нэг дээр нь тэмдэглэсэн зүйл нөгөө
  дээр нь тэр дор нь тусна.
- **Хадгалалт бүтэхгүй бол.** Нууц горим эсвэл хадгалах зай дүүрсэн үед дэлгэцийн
  дээд талд улаан зурвас гарч ирнэ. Чимээгүй алдагдахыг зөвшөөрөхгүй.
- **Гар утасны бус хэрэглээ.** Доод табууд нь жинхэнэ `tablist` — сум товчоор
  таб солино, `Home` / `End` эхэн ба төгсгөл рүү үсэрнэ.
- **Тэмдэглэхэд байрлалаа алдахгүй.** Дэлгэц бүхэлдээ дахин баригддаг ч
  дарсан товчны **фокус** болон хуудасны **скролл** байрандаа үлдэнэ. Урт
  жагсаалтын доод талын сет дарахад дэлгэц эхэн рүүгээ үсрэхгүй, гараар
  ажиллаж байгаа хүн сет бүрийн дараа эхнээс нь `Tab` дарахгүй.

## Яаж ажиллуулах

Апп нь `data/program.json`-ыг `fetch`-ээр уншдаг тул `index.html`-ийг файлаар шууд
нээвэл (`file://`) хөтчийн аюулгүй байдлын дүрмээр ажиллахгүй. Локал сервер хэрэгтэй:

```sh
# repo-гийн үндсэн хавтсанд
python3 -m http.server 8000
```

Дараа нь утас эсвэл хөтчөөс `http://localhost:8000/` руу орно.
(Chrome DevTools дээр төхөөрөмжийн горимыг 360–430px өргөнтэй тохируулж үзэхэд тохиромжтой.)

**GitHub Pages:** repo-г Pages дээр нийтэлхэд ямар ч тохиргоо шаардахгүй. Бүх зам
харьцангуй (`./css/...`, `./js/...`, `./data/...`) тул `/gym-tracker/` гэх мэт дэд
замд байрлуулсан ч ажиллана.

## Офлайн ба суулгах

Заал дээр сүлжээ муу байдаг. Дасгалаа тэмдэглэхийн тулд интернет **шаардлагагүй**:
бүх өгөгдөл аль хэдийн `localStorage` дээр байсан бөгөөд одоо файлууд нь өөрсдөө
хөтчийн кэшэнд суудаг болсон.

- **Офлайн.** Нэг удаа нээсэн бол дараа нь нислэгийн горимд ч бүрэн ажиллана.
- **Утсанд суулгах.** Chrome/Safari дээр "Нүүр дэлгэцэд нэмэх" гэхэд хаягийн
  мөргүй, тусдаа апп шиг нээгддэг болно (`display: standalone`).
- **Гадаад холбоос нэмэгдээгүй.** Workbox гэх мэт library ороогүй — `sw.js` нь
  гараар бичигдсэн, хамааралгүй файл. Icon-ууд ч repo дотор.

| Файл | Юу хийдэг |
| --- | --- |
| `manifest.webmanifest` | Аппын нэр, өнгө, icon — "суулгах" боломжийг өгнө |
| `sw.js` | Service worker: файлуудыг кэшилж, офлайн үед өгнө |
| `js/updates.js` | sw-г бүртгэж, шинэ хувилбар бэлэн болоход зурвас гаргана |
| `icons/*.png` | Дэлгэцийн icon (192, 512, maskable, apple-touch) |

### Шинэчлэлт хэрхэн очих вэ

Кэшлэсэн апп-ын хамгийн том эрсдэл нь "хуучин хувилбар дээр мөнхөд гацах".
Тиймээс кэшийн нэр нь **commit-ийн SHA** дээр тулгуурлана — `pages.yml` нь
deploy бүрд `sw.js` доторх `BUILD` мөрийг солино. Үүнээс үүдэн:

- deploy бүр өөрийн бүтэн кэштэй болно — хуучин, шинэ файл **холилдохгүй**,
- шинэ хувилбар ард нь чимээгүй татагдана, хуучин нь ажилласаар байна,
- бэлэн болмогц дээд талд *"Шинэ хувилбар бэлэн — дарж шинэчил"* зурвас гарна,
- дарах хүртэл юу ч солигдохгүй. Сет тэмдэглэж байх дунд дэлгэц өөрөө
  дахин ачаалагдахгүй.

### Локал хөгжүүлэлт

`http://localhost` дээр service worker ажиллана (`file://` дээр ажиллахгүй —
тэр үед апп зүгээр офлайнгүй, хэвийн ажиллана). Локал дээр `BUILD` нь
тавигдаагүй байдаг тул sw нь **сүлжээг эхэнд** үзнэ: засвар шууд харагдана,
гэхдээ сүлжээ тасрахад кэш нь ажиллаад өгнө. Ингэснээр офлайн зан төлөвийг
локал дээрээ ч шалгаж болно (DevTools → Network → Offline).

Icon-уудыг дахин үүсгэх шаардлага гарвал:

```sh
python3 tools/make-icons.py
```

Энэ бол **build алхам биш** — гараар, ховор дуудагдана. Хамааралгүй (зөвхөн
Python-ий дотоод `zlib`), үр дүн нь `icons/` дотор commit хийгдэнэ.

## Өдөр солих

Хөтөлбөр нь гарагт бэхлэгдсэн (`d1` = Даваа ...). Гэхдээ амьдрал төлөвлөгөөг
дагадаггүй: ажлаас ядраад маргаашийн бэлтгэлээ хийж чадахгүй, оронд нь
амралтын өдрөө нөхөж хийх хэрэг гарна. Тиймээс **өдрийн дэлгэц бүр дээр**
"Энэ бэлтгэлийг өөр өдөр рүү зөөх" (амралтын өдөр дээр "Энэ өдөр бэлтгэл
хийх") гэсэн товч байна.

### Зөөх биш, СОЛИХ

Сонгосон хоёр өдөр **байраа солино**:

```
Өмнө:  Лхагва — Амралт          Пүрэв — Хөл + Хэвлий
Дараа: Лхагва — Хөл + Хэвлий    Пүрэв — Амралт
```

Яагаад зүгээр "зөөдөггүй" вэ: зөвхөн нэг талыг нь зөөвөл эх өдөр нь хоосон
үлдэж, түүх дээр **"хийгээгүй"** болж, цуваа тасарна. Гэтэл тэр өдөр ажил
байхаа больсон — буруутгах шалтгаан алга. Солилцоо нь үргэлж хосоороо явдаг
тул:

- нэг ч бэлтгэл **алга болохгүй, давхарлахгүй**,
- зөөгдсөн өдөр **амралт** болж, цувааг таслахгүй,
- буцаахад хоёр өдөр хоёулаа байрандаа очно.

### Дүрмүүд

- **Тэмдэглэгээтэй өдрийг зөөхгүй.** Хийчихсэн сетүүд шинэ төлөвлөгөөнд
  таарахгүй болж чимээгүй устах эрсдэлтэй. Товчны оронд шалтгаан харагдана —
  тэмдэглэгээгээ авбал дахин зөөх боломжтой болно.
- **Хүрээ нь 14 хоног** — энэ долоо хоногийн Даваагаас эхэлсэн хоёр долоо хоног.
  Өнгөрсөн өдөртэй солих нь "нөхөж хийх" (мартсан бэлтгэлээ өнөөдөр хийх),
  ирээдүйн өдөртэй солих нь "урьдчилж зөөх".
- **Гурав дахь өдөр хосгүй үлдэхгүй.** Аль хэдийн солигдсон өдрийг өөр
  өдөртэй дахин солиход хуучин холбоо эхлээд тайлагдана.
- Долоо хоног ба түүхийн жагсаалт дээр солигдсон өдөр жижиг ⇄ тэмдэгтэй
  харагдана — "яагаад Лхагвад хөл байна?" гэсэн эргэлзээ үлдэхгүй.

Солилцоо нь `gym:state_v1` доторх `swaps` талбарт хадгалагдана (харилцан
хосууд). Хагас холбоос үүсвэл унших үедээ хаягдана.

## Хөтөлбөрөө солих

Бүх дасгал `data/program.json` дотор байдаг. **Код руу юу ч бичих шаардлагагүй** —
энэ нэг файлыг л засна.

### Өдрийн id ↔ гарагийн харгалзаа

Өнөөдрийн өдрийг **гарагийн дугаараар, орон нутгийн цагаар** тодорхойлно:

| id | Гараг | Одоогийн хөтөлбөрт |
| --- | --- | --- |
| `d1` | Даваа | Нуруу + Бицепс |
| `d2` | Мягмар | Мөр + Трицепс |
| `d3` | Лхагва | **Амралт** |
| `d4` | Пүрэв | Хөл + Хэвлий |
| `d5` | Баасан | Нуруу (зузаан) + Дельта |
| `d6` | Бямба | Цээж + Гар |
| `d7` | Ням | **Амралт** |

Өөрөөр хэлбэл `d1` бол үргэлж Даваа. Дасгалуудыг өөр гараг руу зөөх бол
тухайн `dN` дотор байгаа `exercises`-ийг зөөнө — id-г нь солихгүй.

### Файлын хэлбэр

```json
{
  "version": 1,
  "name": "Өргөн мөр, бүтэн нуруу",
  "restDays": ["d3", "d7"],
  "days": [
    {
      "id": "d1",
      "title": "Нуруу + Бицепс",
      "exercises": [
        { "id": "e101", "name": "Bent-over barbell row", "sets": 4, "reps": "8-10", "rest": 150, "note": "Нуруугаа бөхийлгөхгүй" }
      ]
    },
    { "id": "d3", "title": "Амралт", "exercises": [] }
  ]
}
```

- `name` нь гурван дэлгэцийн толгойд жижиг шошго болж гарна — аль хөтөлбөр дээр
  явж байгаагаа ямагт харна.
- `days` дотор **7 өдөр** байна, `d1`-ээс `d7` хүртэл. Амралтын өдөр ч бас
  жагсаалтад орно, зүгээр `"exercises": []` гэж үлдээнэ.
- `restDays` дотор бичсэн id-тай өдөр → амралтын дэлгэц. (Дасгал нь хоосон
  байвал ч мөн адил амралт гэж тооцно.)
- **Дасгалын нэрийг орчуулах шаардлагагүй.** Заалны яриа хэлээр латин/монгол
  холимог байх нь хэвийн — `"Өргөн бариултай таталга / Lat pulldown"` гэх мэтээр
  бичсэн нэр яг тэр хэвээрээ дэлгэц дээр гарна.
- Дасгалын `id` бол хадгалагдсан тэмдэглэгээний холбоос. **Нэр, сет, давталт,
  амралтыг чөлөөтэй солиж болно**, гэхдээ `id`-г солих юм бол тухайн дасгалын
  хуучин тэмдэглэгээ таарахаа болино. (Одоогийн хөтөлбөрт `e101…e107` = d1,
  `e201…` = d2 гэх мэтээр өдрөөрөө бүлэглэсэн.)
- `reps` бол текст — `"8-10"`, `"5"`, `"45 сек"` бүгд болно.
- `rest` бол секундээр. `0` бол харуулахгүй, тоолуур ч ажиллахгүй.
- `note` хоосон байвал картан дээр гарахгүй.

## Дизайн

Бүх өнгө, зай, фонтын хэмжээ `css/base.css`-ийн `:root` дотор хувьсагчаар байна.
Бусад CSS файл зөвхөн `var()`-оор л уншина — шууд утга бичихгүй.

**Дэвсгэр 3 давхарга:** `--bg-1 #0B0B0C` → `--bg-2 #141416` → `--bg-3 #1C1C1F`.
Давхаргыг дэвсгэрийн зэрэглэлээр ялгана — **унжсан сүүдэр (drop shadow)
ашиглахгүй**: харанхуй дэвсгэр дээр сүүдэр харагддаггүй, зөвхөн бохирддог.
Gradient бас байхгүй.

**Гадаргуугийн ирмэг:** `--edge` = `inset 0 1px 0 rgba(255,255,255,0.05)`.
Карт бүрийн дээд ирмэг дээр гарах үл мэдэг цагаан зурвас. Энэ нь сүүдэр биш —
гэрлийн тусгал: дэвсгэрээс "дээгүүр" байгааг нь мэдрүүлэхэд хангалттай,
харагдахаараа бараг мэдэгдэхгүй. Өнгө нэмэхгүй.

**Текст 3 шат:** `--fg #F2F2F3`, `--fg-2 #A8A8AF`, `--fg-3 #85858E`.
Шат бүр өөрийн үүрэгт хангалттай тод (WCAG AA — 4.5:1-ээс дээш). Урьд нь
`--fg-3` нь 3:1 орчим байсан тул огноо, тайлбар нь наранд эсвэл дэлгэцийн
гэрлийг бууруулсан үед уншигдахгүй болдог байв.

**Акцент өнгөгүй:** `--accent #DEDEE3` (зөөлөн саарал). Өнгөт акцент байхгүй тул
харанхуй заалд нүд барахгүй; статус нь саарлын зэрэглэл, жин, тунгалагаар ялгарна.
Акцент дөрвөн газарт л зөвшөөрөгдөнө:

1. идэвхтэй табын заагч,
2. progress bar-ын дүүрэлт,
3. гүйцэтгэсэн сет ба дасгалын тэмдэглэгээ,
4. амралтын тоолуур дуусах агшин.

Бүдэг хувилбар (`--accent-dim`) нь зөвхөн **байршил заахад**: өнөөдрийн мөрийн
зүүн ирмэгийн 2px зурвас, солигдсон өдрийн зурвас. Тодруулга биш, чиглүүлэгч.

**Улаан (`--danger`)** зөвхөн гурван газарт: алдаа, устгах товч, хадгалалт
бүтэхгүй үеийн мэдэгдэл.

**Зааг:** `--line rgba(255,255,255,0.08)`, түлхүү зааг `--line-strong`.

**Зай:** зөвхөн 4px-ийн үржвэр — `--s1 4` … `--s8 32`. Хажуугийн зай 16px,
дасгалын мөр хоорондоо 8px, жагсаалтын мөр хоорондоо 4px.

**Фонт:** системийн стек, гадны фонт татахгүй. Хэмжээний шат
**28 / 20 / 16 / 14 / 12px**, дунд хэмжээ байхгүй. Бүх тоо
`font-variant-numeric: tabular-nums` (`.num` класс).
Гарчигт `letter-spacing: -0.02em`, 12px шошгонд `+0.04em` + том үсэг.

**Булан:** 8px / 12px. Илүү дугуйрахгүй.

**Хэлбэр дахин ашиглана, шинийг зохиохгүй.** Түүхийн чеклистийн нүд нь сетийн
товчтой (`.set`) яг нэг гэр бүл: дугуйрсан дөрвөлжин, дүүрэхдээ акцент, дотроо
чек. "Өдөр солих" ба "Дэлгэрэнгүй" хоёр нь ижил зан төлөвтэй тул нэг л хэлбэр
(`.disclosure`) — тасархай зааг, дэвсгэргүй, задрахад сум эргэнэ.

**Амралтын өдөр карт.** Урьд нь задгай текст байсан тул дэлгэц хагас хоосон
харагддаг байв. Одоо аппын бусад блоктой ижил карт: сарны тэмдэг, том гарчиг,
доор нь жижиг зөвлөмж, тусгаарлагчийн доор дараагийн бэлтгэл.

**Дарах талбар** хамгийн багадаа 44px (`--touch`).

**Тунгалаг давхарга ганц газар:** доод navigation. Жагсаалт доогуур нь гүйхэд
битүү хавтан агуулгыг огтолж хаядаг байсан бол одоо цаанаас нь бага зэрэг
мэдэгдэж, "дээрх давхарга" гэдэг нь мэдрэгдэнэ (`rgba(11,11,12,0.86)` +
`backdrop-filter: blur(14px)`). Дэмждэггүй хөтөч дээр `@supports` нь битүү
дэвсгэр рүү буцаана. Өөр хаана ч blur байхгүй.

**Hover зөвхөн хулганатай төхөөрөмжид.** Апп нь утсанд зориулагдсан тул бүх
хариу `:active` дээр баригдсан. `@media (hover: hover) and (pointer: fine)`
дотор нэмэлт hover төлөв бий — мэдрэгчтэй дэлгэц дээр "наалдсан hover"
гарахгүй.

**Хөдөлгөөн** — бүгд `cubic-bezier(0.2, 0, 0, 1)`, богино:
`--t-press 90ms` (хуруу хүрэх), `--t-tap 140ms` (тэмдэглэх),
`--t-tab 180ms` (таб ба дэлгэц солих), `--t-open 200ms` (сет задрах),
`--t-bar 280ms` (progress гүйх).
Bounce, spring байхгүй. `prefers-reduced-motion: reduce`-ийг хүндэтгэнэ.
Тэмдэглэх хөдөлгөөн зөвхөн **дөнгөж дарсан** мөр/товч дээр тоглоно
(`is-flash`), бусад нь чимээгүй шинэчлэгдэнэ. Ганц үл хамаарах зүйл нь
амралтын тоолуурын шугам — тэр бол цаг тул `linear`-аар жигд гүйнэ.

**Микро-хөдөлгөөний дүрэм: анзаарагдах ёсгүй, зөвхөн мэдрэгдэх ёстой.**
Бүгд `transform` / `opacity` дээр л ажиллана (хөтчид хамгийн хямд хоёр
шинж чанар), 240ms-ээс богино.

| Хаана | Юу болох |
| --- | --- |
| Дарах бүрд | Хүрэхэд `--t-press` (шуурхай), тавихад `--t-tap` (зөөлөн). Ижил хугацаа хоёр тийш явбал товч наалдсан мэт болдог |
| Сет тэмдэглэхэд | Дарсан товчноос цагирган долгион нэг удаа тарна |
| Амралт дуусахад | Тоолуурын хүрээнээс өргөн долгион |
| Дэлгэц/өдөр солиход | Дасгалын мөрүүд, түүхийн тор дараалж унана (тор нь зүүн дээднээс баруун доош) |
| Идэвхтэй таб | Icon нь 1px дээшилнэ — заагчийн гулсалтыг давхар хэлнэ |
| Задардаг жагсаалт | Мөрүүд дараалж унана, хойшлолт 8 мөрөөр таслагдана |

**Гарч ирэх хөдөлгөөн ЗӨВХӨН нэг удаа.** Өдрийн дэлгэц сет тэмдэглэх бүрд,
түүх нь тэмдэглэгээ солигдох бүрд бүхэлдээ дахин зурагддаг. Тэр болгонд
жагсаалт дахин уначихвал дэлгэц анивчсан мэт болно. Тиймээс `ui.js` нь
зөвхөн **дэлгэц солигдоход** `markFresh()` дуудаж, view нь `is-fresh`
классыг нэг удаа тавьж, тэр дороо унтраана.

**Эмодзи ашиглахгүй.** Доод navigation нь icon + текст, бүх icon нь
`js/dom.js` дотор бичигдсэн дотоод SVG.

**Төлөвийн үгсийн сан нэг.** "Биелсэн / Дутуу / Амралт / Хийгээгүй / Удахгүй"
гэсэн таван үг `js/stats.js`-д нэг л газар тодорхойлогдсон бөгөөд гурван дэлгэц
дээр яг ижил утгатай гарна.

## Хадгалалт

Түлхүүр: `gym:state_v1` (namespace нь `gym:`). Бүх өгөгдөл нэг түлхүүр дор JSON-оор.

```json
{
  "version": 2,
  "sessions": {
    "2026-08-18": {
      "date": "2026-08-18",
      "dayId": "d1",
      "done": 3,
      "total": 7,
      "completedAt": "2026-08-18 19:42",
      "sets": { "e101": [true, true, false, false] }
    }
  },
  "swaps": {
    "2026-08-19": "2026-08-20",
    "2026-08-20": "2026-08-19"
  }
}
```

- Огноо **зөвхөн орон нутгийн цагаар** `"YYYY-MM-DD"`. `toISOString()` хаана ч
  ашиглаагүй — цагийн бүсийн шилжилт гарахгүй.
- `version` талбар + `migrate()` байгаа тул схем солигдоход хуучин өгөгдөл эвдэрэхгүй.
  Танихгүй өгөгдөл устахгүй, `gym:backup_*` болж үлддэг. (v1 -> v2 дээр
  `swaps` нэмэгдсэн — хуучин тэмдэглэгээ бүрнээрээ шилжинэ.)
- `swaps` нь өдөр солилцоо: **үргэлж харилцан** (`swaps[a] === b` бол
  `swaps[b] === a`). Хагас холбоос уншихад хаягдана, жилээс хуучирсан нь
  `reconcile()` дээр цэвэрлэгдэнэ.
- Өдрийн үр дүн `{ date, dayId, done, total, completedAt }` цэвэр бүтэцтэй.
  `storage.getDayResult(date)` шууд үүнийг буцаана — гүүр яг үүн дээр тулгуурладаг.
- Бичилт бүтэхгүй бол `storage.getStorageError()` мессеж буцаана. Апп унахгүй,
  ажиллаж байгаа хэвээр — гэхдээ хэрэглэгч ил мэднэ.

### Хуучин өгөгдөл цэвэрлэх

`data/program.json`-ыг сольсны дараа хуучин тэмдэглэгээ шинэ хөтөлбөртэй таарахаа
болино (дасгалын `id` өөр болсон, өдөр амралт болсон гэх мэт). Үүнийг **гараар
хийх шаардлагагүй** — апп ачаалах бүрд `storage.reconcile()` ажиллаж:

- хөтөлбөрөөс алга болсон өдрийн бичлэгийг устгана,
- одоо амралт болсон өдрийн бичлэгийг устгана,
- байхгүй болсон дасгалын сет тэмдэглэгээг хаяна,
- сетийн тоо өөрчлөгдсөн бол уртыг нь тааруулна,
- `done` / `total` / `completedAt`-ыг дахин тооцно,
- ганц ч сет үлдээгүй бол тухайн өдрийг бүхэлд нь устгана,
- хугацаа нь хэтэрсэн өдөр солилцоог хаяна.

Тэмдэглэгээг тулгахдаа **солилцоог тооцно** — зөөгдсөн өдрийн тэмдэглэгээ
хуучин төлөвлөгөөндөө наалдаж үлдэхгүй.

Шинэ хөтөлбөртэй таарч байгаа тэмдэглэгээ хэвээрээ үлдэнэ.

Бүгдийг нь цэвэрлэхийг хүсвэл **Түүх** дэлгэцийн доод талд *"Бүх тэмдэглэгээг
устгах"* товч бий. Санамсаргүй дарахаас сэргийлж хоёр алхамтай — эхний дарахад
баталгаажуулалт болж хувирна, өөр таб руу шилжихэд тайлагдана. Устгасны дараа
буцаах боломжгүй.

### Түүхийн цонх

Түүх хамгийн ихдээ 30 өдөр харуулна, гэхдээ **анхны тэмдэглэгээнээс өмнөх өдрүүд
жагсаалтад орохгүй**. Аппыг өчигдөр суулгасан хүнд "20 өдөр хийгээгүй" гэж
худал зураг үзүүлэх нь утгагүй. Тэмдэглэгээ **огт байхгүй** үед ч мөн адил —
тэр үед доод цонх буюу 7 өдөр л харагдана.

**Цуваа** нь өнөөдрөөс ухраан тоолсон, дараалан биелсэн бэлтгэлийн өдрийн тоо.
Амралтын өдөр цувааг **таслахгүй**, гэхдээ тоонд ч орохгүй. Өнөөдөр хараахан
дуусаагүй байх нь цувааг таслахгүй — өдөр дуусаагүй байхад буруутгах нь эрт.

## Гүүр (`gym:bridge`)

Summer Project энэ апптай **ижил GitHub Pages origin** дээр байрладаг тул
`localStorage`-оо хуваалцдаг. Энэ апп `gym:bridge` түлхүүрт нэг чиглэлтэй
activity feed бичнэ, Summer Project түүнийг **зөвхөн уншиж** XP болгоно.

- Бичдэг цорын ганц түлхүүр нь `gym:bridge`. `gym:state_v1`-д гүүр хэзээ ч бичихгүй.
- `summerProjectWebData_v4` буюу нөгөө талын өгөгдлийг **уншихгүй**.
- **XP-ийн тооцоо энд байхгүй.** Энэ апп зөвхөн "юу болсныг" мэдээлнэ, хэдэн XP
  болохыг Summer Project-ийн `XP_RULES` шийднэ.
- Гүүрийн UI байхгүй — тэмдэглэгээ бичигдэх бүрд (болон таб руу буцаж ирэхэд)
  чимээгүй шинэчлэгдэнэ. Агуулга нь өөрчлөгдөөгүй бол дахин бичихгүй.

```json
{
  "v": 1,
  "app": "gym",
  "label": "Gym",
  "updatedAt": 1787208109485,
  "status": {
    "todayPlan": "Хөл + Хэвлий",
    "todayProgress": "3/7",
    "lastWorkout": "2026-08-20"
  },
  "events": [
    {
      "id": "gym-2026-08-18",
      "at": 1787082120000,
      "type": "workout.completed",
      "value": 7,
      "detail": "7/7 · Мөр + Трицепс"
    },
    {
      "id": "gym-2026-08-20",
      "at": 1787227200000,
      "type": "workout.partial",
      "value": 3,
      "detail": "3/7 · Хөл + Хэвлий"
    }
  ]
}
```

- **Дасгалын өдөр бүрд НЭГ event**, `id` нь `gym-<YYYY-MM-DD>`. Өдрийг дахин
  нээж, дахин тэмдэглэсэн ч уншигч тал `id`-гаар шүүдэг тул давхар тоологдохгүй.
  Өнгөрсөн өдрийг нөхөж тэмдэглэсэн ч энэ дүрэм л үйлчилнэ — тухайн өдрийн event
  шинэчлэгдэнэ, шинэ event үүсэхгүй.
- `type` нь бүх дасгал тэмдэглэгдсэн бол `workout.completed`, эс бөгөөс
  `workout.partial`. Өдрийн явцад `partial` бичигдээд дараа нь `completed` болж
  сайжирч болно — сүүлчийн утга нь тухайн өдрийн эцсийн байдал.
- `value` = дуусгасан дасгалын тоо. `detail` = `"<хийсэн>/<нийт> · <өдрийн нэр>"`.
- Нэг ч дасгал бүтэн дуусгаагүй өдөр болон амралтын өдөр event үүсгэхгүй.
- Сүүлийн 14 хоногийн дасгал л feed-д ордог (`lastWorkout` нь 30 хоногийг хардаг).

Уншигч тал дээр нэмэх мөр (`summer-project/bridge.js`, `BRIDGE_SOURCES`):

```js
{ app: "gym", key: "gym:bridge", label: "Gym", skillId: GYM_SKILL_ID, categoryId: "fitness" }
```

## Тест ба төрлийн шалгалт

Апп нь ажиллахдаа ямар ч хамааралгүй (build алхам байхгүй, `node_modules`
шаардахгүй). Тест нь Node-ийн дотоод `node:test` дээр шууд ажиллана:

```sh
npm test          # node --test "tests/*.test.js"
```

Тестүүд хөтөч шаардахгүй: `tests/helpers.js` нь санах ойд ажиллах
`localStorage` / `sessionStorage` суулгаж өгдөг (зай дүүрэх, унших хаагдах зэрэг
эвдрэлийг зориудаар дуурайж чадна).

| Файл | Юуг барьдаг |
| --- | --- |
| `tests/data.test.js` | Огнооны хэлбэр, сар/жилийн зааг, DST, орон нутгийн цаг |
| `tests/program.test.js` | Гараар засагдсан JSON: давхардсан id, дутуу талбар, хязгаар |
| `tests/storage.test.js` | Схем, migration, эвдэрсэн өгөгдлийг нөөцлөх, `reconcile` |
| `tests/stats.test.js` | Цуваа, долоо хоног/түүхийн хураангуй, төлөвийн ялгаа |
| `tests/schedule.test.js` | Өдөр солилцоо: харилцан хос, буцаалт, цуваа, migration |
| `tests/timer.test.js` | Тоолуурын амьдралын мөчлөг, дахин ачаалалтыг давах |
| `tests/bridge.test.js` | `gym:bridge` гэрээ — уншигч тал үүнд найддаг |
| `tests/safe-storage.test.js` | Нууц горим, зай дүүрэх, эвдэрсэн JSON |
| `tests/pwa.test.js` | Офлайн кэш бүрэн эсэх, manifest, icon, хувилбарын мөр |

**Төрлийн шалгалт.** Код нь энгийн JS хэвээр (түгээлтэнд TypeScript ордоггүй),
харин бүх нийтлэг бүтэц `js/types.js` дотор JSDoc-оор тодорхойлогдсон бөгөөд
`jsconfig.json` дахь `checkJs: true` нь тэдгээрийг **бодит шалгалт** болгоно:

```sh
npx typescript@5.7 tsc --noEmit -p jsconfig.json
```

Хоёулаа `.github/workflows/ci.yml` дотор push / PR бүр дээр ажиллана. Мөн
Pages рүү deploy хийхээс өмнө тест ажиллана — унасан код амьд сайт руу гарахгүй.
